Running Cycling Analysis Profile

Last updated 30 October 2026

Privacy policy

Analysis runs in your browser. Without an account, files are not uploaded. With an account, your profile and activity summaries are stored on Cloudflare, and original files only if you choose. We do not sell your data, and the app has no analytics or advertising trackers.

RunningCyclingAnalysis is run by Bryce Capuano, and its source is public on GitHub. Privacy requests go to the repository's issues. Do not put personal data in them.

Without an account

  • Each activity's summary is kept in this browser's IndexedDB where the browser allows, so results survive a reload, and anyone using this browser can see them. It holds the figures shown: times, distances, elevation gain, the power source (measured, estimated or none), splits per km and mile (flat-pace times, climb and heart rate), moving time, heart-rate and power, average power, best efforts, climbs, power-meter calibration sums, the indoor flag and data-quality flags, a mark on a run at walking pace, a race mark when a Strava export tags the activity as a race, and the file name. Its name comes from the activity list in a Strava export or the activity summaries in a Garmin export, else the title in the file, else the start time and sport. A name from an export is kept as the export writes it, and can name a place. For an outdoor activity with GPS it also holds an outline of the route with no coordinates or scale. The outline is kept only in this browser and is never uploaded. The summary has no per-second data or original file, and it does not expire. When one file yields several summaries, including a split activity, each keeps a SHA-256 hash of that file, so they are shown together. Summaries kept from now on also keep the file name and a SHA-256 hash of the file, for adding them to an account later.
  • Settings are kept in this browser's local storage: weight, bike and gear weight, units, year and sex if given, whether setup is answered (rca.setup.v1, one answer for the whole browser), and the view period you pick, under rca.period.v1. This copy is kept whether or not you have an account: signing out, deleting your account and Remove all my activities leave it, and the next person using this browser can see it. Clearing this site's data removes it. A flag named rca.aboutDataSeen records which data notes you have read. Signing out and Remove all my activities remove it; deleting your account leaves it.
  • Dated settings you add on Profile when signed out, a weight, max heart rate or threshold from a date, are kept in this browser's local storage under rca.measurements.v1. Signed in, they are kept in your account instead.
  • If you choose to keep the power of a ride that the analysis set aside as implausible, the ride's id is kept in this browser's local storage under rca.keepPower.v1. It is never uploaded, signed in or not, and it holds no activity data. Signing out, deleting your account and Remove all my activities clear it; a session that expires does not.
  • A flag in this browser's local storage, named rca.kept.v1, says whether this browser had results to show at its last visit, signed in or not, so a reload can show them at once. It holds no activity data.
  • A database in this browser, named rca-checkin, remembers which files of yours the app has already read, so adding the same export again does not read each file again. For each file it keeps a SHA-256 hash of the file, its size, the sport and start second of the workouts in it, a short signature of what the export's list says about it, and the model revision it was read with. The same database keeps a short summary of the library as it stood before your last import, so the page can say what that import changed: the sport and start second of each workout, counts, the values and dates of your best efforts, the state words of your fitness card and the dates of the changes your years list, and whether you have seen what was said. It holds no names, routes or heart rates, and it is never uploaded. Remove all my activities, signing out and deleting your account clear it, and signing in as someone else clears the other account's rows. Nothing is written for a session that keeps nothing in this browser.
  • A second flag, named rca.deviceKept.v1, says whether the summaries kept in this browser were there at the last visit, so the app can tell you when the browser has cleared them. It holds no activity data. After your first import is kept, the app also asks the browser to keep this site's storage, which sends nothing anywhere. If the browser will not, the app says so once and notes that in a third flag, rca.persistNote.v1.
  • A short record of each import is kept in this browser (database rca-import-meta): the names and sizes of the files it was given (the first 50 of a large drop), how many activity files it read, and whether it finished. It lets a page that loads after an import was cut off say so. The last five per library are kept. A record is dropped once a later import makes it whole. A random id for the tab, with no link to you, is kept in this tab's session storage (rca.importTab.v1) so a reload can tell what it left behind. It is never uploaded. Signing out and deleting your account clear the account's, and so does Remove all my activities, which is offered only when signed out.
  • If you choose to count a run that is at walking pace, the choice is kept in this browser's local storage under rca.countedRuns.v1 as the run's sport and start time in seconds. It is never uploaded, signed in or not. Signing out and deleting your account clear it, and so does Remove all my activities, which is offered only when signed out.
  • The name printed on a shared card stays in this browser: it is kept in local storage under rca.card-name.v1, and it is never uploaded, signed in or not. It is printed only on a card you share or save, and clearing this site's data removes it.

Signing out does not remove these summaries, and they are not shown while you are signed in. Remove all my activities, offered on Profile only when signed out, removes them, as does clearing this site's data.

Activity detail recordings on this device

The activity workbench also keeps a bounded recording cache in this browser’s IndexedDB. It holds recorded speed, distance, altitude, heart rate, power, cadence and temperature when present, plus pause markers and lap boundaries. It contains no GPS coordinates or original files and is not uploaded. Recording data is limited to 64 MiB across this browser’s cache; the recordings of the oldest activities are removed first to make room. Summaries remain available after a recording is removed. Re-import its file to restore the detailed view, or explicitly read a retained original from your account when one is available.

Account recordings are kept separately from signed-out recordings and other accounts. They are removed from this browser when you sign out. If the browser refuses that cleanup they stay, and the app reads them only for their account. Deleting an activity removes its cached recording, and Remove all my activities removes signed-out recordings. Account deletion also attempts to remove that account’s recordings and reports a local cleanup failure separately. Clearing this site’s browser data removes all recording caches. The cache also keeps one small record for each account that signed out or was deleted in this browser, holding an account identifier and a time, so that a late write for that account is refused. The record for a deleted account stays until you clear this site’s data. The record for a sign-out ends the next time that account signs in here.

Saves waiting on this device

Signed in, each activity is first written to a waiting list in this browser’s IndexedDB and saved to your library from there. The list holds the same activity summary the account keeps (name, sport, start, file name and hash, distance, duration, elevation gain and the figures from the analysis). It holds no route, per-second recording or original file. An entry is removed once your library has the activity. If you close the page or lose your connection first, the saves resume the next time you sign in on this device. Signing out asks first when saves are still waiting, then removes the list, and so does deleting your account. Remove all my activities removes every waiting save from this browser too. When a session ends on its own, the list stays so those saves can finish when you sign in again.

Activities this browser kept before you signed in are offered to the account you sign in to, by email address. Adding them saves each one to the account as an import would, with the file name and hash it was kept with, but without its route, and removes the copy from this browser once the account has it. Not now keeps them here. Remove from this browser deletes them without changing the account.

With an account

You sign in with Google, using only the openid, email and profile permissions. We never receive your password. Signed in, each activity you analyse is saved to your library, and we keep these until you delete them or delete your account:

  • Account: Google account ID, email, display name, and profile picture address (loaded from Google), and when the account was created.
  • Sign-in sessions: a one-way hash of your session token, your account, and its creation and expiry times. The token stays in your browser, in a sign-in cookie that has an expiry date and stays after you close the browser. Sessions end up to 30 days after last use, and at most 90 days after they were created. At most ten are kept; signing in again ends the oldest. Expired sessions are removed in daily cleanup.
  • Profile settings: weight, bike and gear weight, units, whether you keep original files, and year of birth and sex if given.
  • Dated settings: each weight, max heart rate, threshold power or threshold pace you add on Profile, with the date it takes effect, and for the heart rate and thresholds the sport. Each also records when you last changed it. At most 200.
  • Activity summaries: name (as in the summary kept in this browser), sport, start and save times; file name and SHA-256 hash; distance, duration and elevation gain; and the analysis summary, the same figures as the summary kept in this browser. No per-second recording or route data. A name can name a place, and in a Strava export the file name is the number of the activity on Strava.
  • What the analysis summary holds: the activity's id and name; its sport, start time and duration; its distance and elevation gain; whether it has a heart rate and whether it was indoors; how its power was found (measured, estimated or none); quality flags with a count for each kind; the highest heart rate and the average heart rate and power; the time spent moving; best efforts at each length, and by distance for a run; split times; heart-rate blocks; climbs; calibration sums; distributions of heart rate, power and speed; durability and drift figures; a key made from sport and start; whether it was marked a race or a walking pace; and the version numbers of the summary and of the analysis that made it. From model revision 7 it also holds the middle air temperature the device recorded, with the share of the activity that has one; the label you gave the activity in your Strava export's list (Walk, Hike, Ski or another type); and the local calendar day of the activity compared with its UTC day (one earlier, the same or one later). That shift is not a place and not a UTC offset. Read with the start times, it narrows your time zone to a band of hours, and to about one zone if you often train near local midnight. It is read from the file, never from your device.
  • Original files: only while Keep original files in my library is on, and uploaded only then. An original holds your full GPS track, including where you start and finish, and every recorded second of heart rate and power. It is stored in Cloudflare R2, and whoever runs this service can read it. Turning it off deletes them and keeps the summaries. A route outline is drawn from your original only when you ask for it, with Show route.
  • Daily counts: per account, downloads, saves, deletions, uploads, profile changes, dated-setting changes and library reads, kept about a week, up to eight UTC days. When you create or delete an account, a one-way code made from your Google ID with a server key is written beside the number of accounts that ID has created today and, on deletion, that day's counts. These are kept about two days. They hold no name, email or activity, and stop deleting an account and signing up again the same day from resetting the counts.
  • Deletion record: when you delete your account, a random account ID and the time are kept for 100 days, so that restoring the database from an older copy does not bring your account back. It holds no name, email, Google ID or activity.
  • Bookkeeping: activity IDs, a key from each activity's sport and start, digest versions, your activity count and digest bytes, whether and when deletion started, when your profile last changed, and an upload reservation token while a file uploads.

Signed in, your settings are also kept in this browser's local storage, so signing out shows your latest values.

Storage, logs and backups

Accounts, sessions, settings, summaries, daily counts and the size of each kept original are in a Cloudflare D1 database, with short-lived rows for uploads in progress and for account deletions not yet finished. Original files are in a private Cloudflare R2 bucket, under keys that include your account and activity IDs. Cloudflare hosts and processes this data as our provider, and Google processes sign-in.

Cloudflare also keeps a point-in-time history of the database, between 7 and 30 days depending on the plan, which lets us undo a bad deploy. Data you delete can stay in that history until it expires. Deleted accounts are removed again if we ever rewind the database.

Error logs hold a request ID, the error type and, for a saved activity that cannot be read, its ID. They never hold request bodies, files, tokens or query strings. Cloudflare's request logs may include each request's network address, approximate location, browser user agent and the address of the request (URL), which can carry the one-time Google sign-in code and state, and the code cannot be reused. The network address is used only as a rate-limit key. Request and error logs are kept three days on Cloudflare's Free plan; retention depends on the plan.

Cookies are strictly necessary only: the sign-in cookie, and two cookies that last ten minutes and protect the Google sign-in. There are no tracking or advertising cookies.

If backups are run, each is an encrypted archive of the database: account identifiers, email addresses, session hashes and activity summaries, plus a list of original-file keys and sizes, but not the files. It is a downloadable artifact of the public GitHub repository, so anyone who can read the repository can download it. Age encryption is its only protection, and the private key is kept outside GitHub. Each archive is kept up to 90 days, then deleted, and deleted data can remain in backups until then.

How to delete your data

On the Profile page you can:

  • Turn off Keep original files in my library to delete stored originals and keep summaries.
  • Delete one activity from Saved library, or from Kept in this browser when signed out. This removes its summary and any original file at once, or in the next daily cleanup if deleting the file fails.
  • Choose Remove all my activities when signed out to remove every summary kept in this browser.
  • Clear your year of birth, or choose Prefer not to say for sex.
  • Choose Delete account. It removes your account, sessions, profile, dated settings, activity summaries and original files. It does not clear this browser's copy of your settings or summaries kept here before you signed in, until you clear this site's data or use Remove all my activities while signed out.

Your data file

Signed in, Download my data on the Profile page gives one JSON file: its format and time, your account name and email, profile settings, your dated settings, and each saved activity's ID, sport, start, name, file name, whether an original is stored, save time and summary. It has no original files, and it says how many saved activities could not be read.

Rights and changes

You may have rights to access, correct, delete or restrict your data, which you can request as above. The service is not directed at children, and this page's date changes with the policy.
